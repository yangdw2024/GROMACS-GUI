## 二、使用场景

### 场景1：修改代码后验证无副作用
```bash
# 修改了版本管理相关代码
python test_cases/test_phase2_regression.py
python test_cases/test_3_2_version_compat.py
```

### 场景2：用户报告内存问题
```bash
python test_cases/test_3_1_memory_stress.py
# 查看输出的隐患清单
```

### 场景3：版本升级后验证
```bash
python test_cases/test_phase1_fixes.py
python test_cases/test_phase4_hardening.py
```

### 场景4：全量回归测试
```bash
# 依次运行全部脚本
for f in test_cases/test_*.py; do echo "=== $f ==="; python "$f" 2>&1; done
```

## 三、输出解读

### 隐患清单格式
```
【隐患 #1】
隐患描述：内存限制设为999GB未被拦截
复现步骤：设置 simulation.mem_limit_gb=999
严重程度：HIGH
```

### 严重程度定义
| 等级 | 含义 | 处理建议 |
|------|------|----------|
| HIGH | 可导致程序崩溃或数据丢失 | 必须修复 |
| MEDIUM | 影响功能但不会崩溃 | 建议修复 |
| LOW | 体验不佳或极端场景 | 择机修复 |

## 四、常见问题

### Q1：脚本运行报错"No module named 'core'"
**A**：确保在项目根目录运行，且source目录下有core模块。

### Q2：GUI测试脚本无法显示窗口
**A**：确保有可用的显示环境。远程环境需配置DISPLAY。

### Q3：如何只运行特定测试？
**A**：直接运行单个脚本即可，各脚本独立无依赖。
