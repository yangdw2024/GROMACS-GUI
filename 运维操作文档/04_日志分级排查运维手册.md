# 日志分级排查运维手册

## 一、日志级别说明

### 1.1 四个日志级别
系统按重要性将日志分为四个级别，分别存储在独立文件中：

| 级别 | 文件前缀 | 用途 | 保留策略 |
|------|----------|------|----------|
| **DEBUG** | `debug_*.log` | 调试信息、详细执行流程 | 超期自动清理 |
| **INFO** | `info_*.log` | 正常运行信息、状态变更 | 超期自动清理 |
| **WARNING** | `warning_*.log` | 潜在问题、非致命错误 | 超期自动清理 |
| **ERROR** | `error_*.log` | 严重错误、崩溃、失败 | **永久保留** |

### 1.2 日志文件命名
```
{级别}_{时间戳}.log
例：error_20260709_201500.log
```

## 二、各级别日志适用场景

### 2.1 DEBUG日志
- 函数调用跟踪
- 变量值记录
- 性能调试信息
- 开发阶段问题定位

**使用建议**：仅在开发调试时启用，生产环境建议关闭以减少磁盘占用。

### 2.2 INFO日志
- 程序启动/关闭
- 用户操作记录
- 模块加载状态
- 模拟任务开始/完成

**使用建议**：默认启用，用于了解程序运行状态。

### 2.3 WARNING日志
- 配置缺失使用默认值
- 资源接近上限
- 非致命命令失败
- 兼容性提示

**使用建议**：关注但通常不影响程序运行。

### 2.4 ERROR日志（关键）
- 程序崩溃
- 模块加载失败
- GROMACS命令执行失败
- 编译错误
- 文件读写失败

**使用建议**：**必须重点关注**，用于定位核心问题。

## 三、日志自动清理规则

### 3.1 过期清理机制
- 默认保留**30天**
- 可通过GUI自定义（1-365天）
- 自动按文件修改时间（mtime）判断
- 程序启动时自动执行清理

### 3.2 ERROR日志特殊处理
- **永久保留，不参与自动清理**
- 用于长期问题追踪和历史回溯
- 需手动管理

### 3.3 手动清理
通过【系统清理】功能：
1. 勾选"清理过期日志"
2. 设置保留天数
3. 执行清理

## 四、通过ERROR日志定位问题

### 4.1 编译失败排查

**典型ERROR日志内容**：
```
[2026-07-09 14:23:15] [ERROR] gmx.exe执行失败: 找不到CUDA库
[2026-07-09 14:23:15] [ERROR] CUDA运行时库缺失或损坏
```

**排查步骤**：
1. 打开ERROR日志文件
2. 定位错误时间点
3. 查看具体错误信息
4. 对照解决方案：
   - CUDA库缺失：检查`bin/`目录下`cudart64_*.dll`、`cufft64_*.dll`
   - 环境变量错误：检查GMXLIB、PATH配置
   - 编译参数错误：检查CMAKE配置

### 4.2 运行崩溃排查

**典型ERROR日志内容**：
```
[2026-07-09 15:30:22] [ERROR] mdrun执行异常: PME grid error
[2026-07-09 15:30:22] [ERROR] PME网格参数不兼容
```

**排查步骤**：
1. 记录崩溃发生的模拟阶段
2. 检查md.mdp中PME相关参数
3. 对照GROMACS报错信息调整参数

### 4.3 PLUMED相关问题

**典型ERROR日志内容**：
```
[2026-07-09 16:45:33] [ERROR] PLUMED库文件损坏: libplumedKernel.dll为空
```

**排查步骤**：
1. 检查PLUMED版本完整性
2. 验证动态/静态链接状态
3. 重新编译或下载完整PLUMED包

## 五、日志查看快捷入口

### 5.1 打开日志目录
点击GUI工具栏的【日志目录】按钮，选择：
- **ERROR日志目录**：直接定位到error日志区域
- **全量日志目录**：打开完整日志文件夹

### 5.2 日志文件位置
```
source/logs/
├── error_20260709_201500.log
├── warning_20260709_201500.log
├── info_20260709_201500.log
├── debug_20260709_201500.log
└── gromacs_gui_20260709_201500.log  (主日志，包含全部级别)
```

## 六、常见问题解答

### Q1：日志文件占用太多磁盘空间？
**A**：使用【系统清理】功能，设置较短保留天数（如7天）清理非ERROR日志。

### Q2：为什么我的ERROR日志没有记录？
**A**：ERROR日志仅在发生错误时创建。如无错误则不生成该文件。

### Q3：如何查看历史运行状态？
**A**：INFO日志记录正常运行状态，ERROR日志记录问题。结合使用可还原历史状态。

### Q4：日志中包含中文乱码怎么办？
**A**：使用支持UTF-8的文本编辑器（如VS Code、Notepad++）打开。

## 七、最佳实践

### 7.1 定期检查
- 每周检查ERROR日志目录
- 关注WARNING日志中的潜在问题提示
- 定期清理过期日志释放空间

### 7.2 问题归档
- 将ERROR日志关键片段复制保存到问题跟踪系统
- 记录解决方案便于后续参考
- 建立常见错误对照表

### 7.3 日志级别调整
开发调试阶段可临时调整日志级别：
```python
# 在代码中设置
logger.set_level(LogLevel.DEBUG)  # 输出最详细日志
logger.set_level(LogLevel.INFO)   # 正常模式
logger.set_level(LogLevel.ERROR)  # 仅记录错误
```
