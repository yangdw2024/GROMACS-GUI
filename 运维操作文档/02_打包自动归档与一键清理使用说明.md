# 打包自动归档与一键清理使用说明

## 一、打包自动归档机制

### 1.1 自动归档功能说明
执行`build_scripts/build_release.bat`打包完成后，系统自动执行以下操作：
1. 将release目录压缩为ZIP包
2. 保存到`archives/release_backup/`目录
3. 按时间戳命名：`GROMACS_GUI_v4.2.0_20260709_201500.zip`
4. 自动清理超限的旧备份

### 1.2 备份阈值配置
在`version.config`中配置最大备份数量：

```json
{
  "backup_max_count": 5
}
```

当备份数量超过阈值时，自动删除最早的旧备份。

### 1.3 归档文件命名规则
```
{产品名}_{版本号}_{时间戳}.zip
例：GROMACS_GUI_v4.2.0_20260709_201500.zip
```

## 二、一键清理功能

### 2.1 打开清理对话框
点击GUI工具栏的【系统清理】按钮。

### 2.2 双选项清理

对话框提供两个独立的清理选项：

| 选项 | 清理内容 | 影响范围 |
|------|----------|----------|
| **清理临时缓存** | `__pycache__`、`.pyc`、`.spec`、旧exe、残留文件 | 不影响核心数据和配置 |
| **清理过期日志** | INFO/DEBUG/WARNING级别超过指定天数的日志 | **ERROR日志永久保留** |

### 2.3 日志保留天数配置
- 默认保留30天
- 可自定义范围：1-365天
- 仅清理INFO/DEBUG/WARNING级别
- ERROR日志永久保留，不会被清理

### 2.4 操作步骤

1. 点击【系统清理】按钮
2. 选择要执行的清理选项（可单选或多选）
3. 设置日志保留天数（默认30天）
4. 点击确定执行清理
5. 查看清理结果弹窗

## 三、手动归档备份

### 3.1 查看归档备份
归档备份目录：`archives/release_backup/`

### 3.2 手动删除备份
如需手动清理旧备份：
1. 进入`archives/release_backup/`目录
2. 删除不需要的ZIP文件
3. 建议保留最近3-5个版本备份

---

## 四、注意事项

### 4.1 清理前备份
- 系统清理前会自动备份`config/app_config.json`
- 清理失败不影响原配置文件

### 4.2 ERROR日志不清理
- 错误日志包含重要诊断信息
- 用于定位编译失败、运行崩溃等问题
- 需手动管理或长期保存

### 4.3 磁盘空间管理
建议定期检查：
- `archives/release_backup/`备份目录大小
- `source/logs/`日志目录大小
- `temp/`临时文件目录

## 五、常见问题解答

### Q1：打包后找不到归档备份？
**A**：归档备份保存在项目根目录的`archives/release_backup/`文件夹中。

### Q2：清理后程序运行异常？
**A**：一键清理仅删除缓存和过期日志，不影响核心代码。如有问题请检查ERROR日志。

### Q3：如何查看清理了哪些文件？
**A**：清理完成后会弹窗显示清理文件数量和释放的磁盘空间。
