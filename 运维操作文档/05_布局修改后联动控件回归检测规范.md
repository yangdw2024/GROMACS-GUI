# 布局修改后联动控件回归检测规范

## 一、检测时机

以下场景修改后，**必须执行完整联动回归检测**：
1. 修改顶部系统配置区域（Part 1）的控件布局
2. 修改版本下拉框、GPU开关、内存限制、线程数相关代码
3. 修改`_on_version_changed`版本切换回调
4. 修改`_load_persistent_config`/`_save_persistent_config`配置持久化
5. 修改`run_command`命令执行入口

## 二、检测步骤

### 步骤1：版本切换联动
1. 记录当前内存限制值、GPU开关状态、线程数
2. 遍历全部GROMACS版本，逐一切换
3. 每次切换后验证：内存值、GPU开关、线程数**不被重置**
4. 切换完成后验证配置持久化正确

### 步骤2：配置持久化联动
1. 修改内存限制值（如从8GB改为10GB）
2. 关闭程序
3. 重新启动程序
4. 验证内存值仍为10GB

### 步骤3：GPU开关联动
1. 开启/关闭GPU开关
2. 切换GROMACS版本
3. 验证GPU状态不被重置

### 步骤4：图标稳定性
1. 连续创建5次GUI实例并关闭
2. 每次验证图标正常加载

## 三、自动化检测命令

```bash
python test_cases/test_phase2_regression.py
```

## 四、验收标准

| 检测项 | 通过条件 |
|--------|----------|
| 版本切换 | 遍历全部版本后内存/GPU/线程数不变 |
| 配置持久化 | 重启后配置值与关闭前一致 |
| GPU开关 | 切换版本后GPU状态保持 |
| 图标稳定性 | 5次创建/销毁均正常加载 |

## 五、常见联动失效模式

| 现象 | 原因 | 修复方法 |
|------|------|----------|
| 版本切换后内存重置 | `_on_version_changed`中未保留配置 | 确保版本切换不修改非版本相关控件 |
| 重启后配置丢失 | `closeEvent`未保存 或 `_load_persistent_config`未加载 | 检查save/load逻辑 |
| GPU开关被重置 | 版本切换时重新初始化GPU控件 | 版本切换时仅更新版本相关信息 |
